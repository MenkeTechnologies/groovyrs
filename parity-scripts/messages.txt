# Probe corpus for the exception-MESSAGE audit — run it the same way as
# `probes.txt`:  bash parity-scripts/fuzz.sh parity-scripts/messages.txt
#
# Why this file is separate from `probes.txt`. The harness wraps every probe in
# `catch (Throwable t) { println "EXC:" + t.getClass().getName() }`, so a probe
# that merely throws is compared on its exception *class* and nothing else. The
# message text — the part a `format!` in the Rust source produces — is never
# looked at. A message can be the wording of a JDK that is not the oracle's and
# still pass every probe in `probes.txt`.
#
# That is not hypothetical. `"ab".substring(0, 9)` carried
# `begin 0, end 9, length 2`, the JDK 17 wording, frozen in the Rust source,
# while the sibling subscript path already emitted JDK 19's
# `Range [0, 9) out of bounds for length 2` — two spellings of one bound, from
# one build. The version gate in `oracle-jvm.sh` cannot see a string frozen in
# the source, and neither can a probe that only prints a class name.
#
# So every probe here prints `class | message`. Each one triggers a distinct
# message-producing site in `src/host.rs`. Adding a `raise(…)` with new wording
# means adding the probe that pins it.
#
# Probes are separated by a line containing only `%%`.
# ── String bounds: three separate sites, one JDK wording ──
try { "ab"[9] } catch (Throwable t) { println t.getClass().getName() + ' | ' + t.message }
%%
try { "ab".substring(0, 9) } catch (Throwable t) { println t.getClass().getName() + ' | ' + t.message }
%%
try { "ab".substring(5) } catch (Throwable t) { println t.getClass().getName() + ' | ' + t.message }
%%
try { "ab".charAt(9) } catch (Throwable t) { println t.getClass().getName() + ' | ' + t.message }
%%
try { "abcdef".substring(4, 2) } catch (Throwable t) { println t.getClass().getName() + ' | ' + t.message }
%%
try { "ab"[-9] } catch (Throwable t) { println t.getClass().getName() + ' | ' + t.message }
